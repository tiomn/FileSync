# 文件同步助手（FileSync）技术方案 v1.1

> 目标：Windows 桌面应用，双击 exe 弹出窗口；配置「监听目录 → 目标目录」，监听目录内
> 文件发生变化后按选定模式复制到目标目录；支持手动 / 自动同步、变更通知与完成通知、
> 历史配置方案列表。

> **选型已确认：Tauri 2（Rust 后端 + 原生 WebView2 前端）**

## 三、构建链方案（已解决，无需管理员权限）

实测本机：Rust 1.95 可用，但 **Visual Studio Community 2022 未安装 C++ 工作负载**
（无 `VC\Tools\MSVC`），**Windows SDK 缺失**，当前会话**非管理员**，实测 `cargo build` 报
`linker 'link.exe' not found`。

Rust 自带的 `x86_64-pc-windows-gnullvm` / `windows-gnu` 目标的 `self-contained` 目录中
**只有 `crt2.o` / `dllcrt2.o`**，不含 mingw 导入库（`libkernel32.a`、`libmingw32.a` 等），
无法真正自包含链接。

### 最终采用的方案

**便携版 mingw-w64（w64devkit）+ Rust `x86_64-pc-windows-gnu`**，全程免安装、免管理员：

```
scripts/setup-toolchain.ps1   # 下载 w64devkit(约64MB) 到 %LOCALAPPDATA%\FileSync-tools
                              # + rustup target add x86_64-pc-windows-gnu
                              # + rustup toolchain install stable-x86_64-pc-windows-gnu
scripts/build.ps1 -Release    # 用 mingw 的 gcc 作链接器，产出 exe（需与 WebView2Loader.dll 同目录）
```

要点：
- `CARGO_TARGET_X86_64_PC_WINDOWS_GNU_LINKER` 指向 w64devkit 的 `gcc.exe`
- 设置 `WINDRES` 指向 w64devkit 的 `windres.exe`，使 Tauri 能嵌入图标与清单
- **必须使用 gnu 宿主的 rustup 工具链**（`cargo +stable-x86_64-pc-windows-gnu`）。
  仅加 `--target` 不够：build script 与 proc-macro 是按**宿主**目标编译的，默认宿主是
  `x86_64-pc-windows-msvc`，仍会去找 `link.exe`。
- w64devkit 是纯 C 工具链、缺 `libgcc_eh.a`，脚本已补一个空归档满足链接器
- 两个 `.ps1` 必须保存为 **UTF-8 with BOM**：Windows PowerShell 5.1 无 BOM 时按 GBK
  解码，中文注释会把紧随其后的语句吞掉
- 产物：`src-tauri/target/x86_64-pc-windows-gnu/release/FileSync.exe`（约 5.4 MB，`strip` 后）

> 备选：若日后安装了 VS 的 C++ 工作负载，可直接 `cargo build --release` 走 msvc 目标，
> 代码无需任何改动。

## 五、核心流程

### 5.1 自动同步主流程

```
「开始监听」
  └─ 校验：源≠目标 / 目标不在源内部；目标目录不存在则自动创建
  └─ 监听目录不存在？ → 进入「等待重试」（见 5.5），不报错退出
  └─ notify 递归监听源目录（默认 1s 防抖窗口，可在界面调整）
       └─ 首次建立 / 目录恢复时立即比对两个目录（见 5.6）
            ├─ 无差异 → 静默继续监听
            └─ 有差异 → 弹窗询问是否立即同步
       └─ 变更事件到达 → 累计条数
            └─ 防抖窗口内无新事件时触发 handle_change
                 ├─ 正在同步中 → 仅置「待同步」，本轮结束后自动续跑
                 ├─ 方式=自动 → 立即同步
                 └─ 方式=手动 → 置「待同步 N 项」（角标 + 状态栏）
                      └─ 可同步通知开启 → 「检测到文件变更」系统通知
                           └─ 用户点「立即同步」
                                └─ sync::run_sync(mode)
                                     ├─ 遍历源目录生成清单（排除规则过滤）
                                     ├─ 逐个比对并按需复制（原子写入 + 占用重试）
                                     ├─ 整体模式：目标多余项 → 回收站
                                     └─ 汇总统计 → 完成通知 → 写入历史/日志
```

### 5.2 差异判定规则

1. 目标不存在 → 复制
2. 目标同名但是目录 → 复制
3. 大小不同 → 复制
4. 大小相同且「源 mtime > 目标 mtime + 2s」→ 复制（容忍时间精度差异）
5. 其余 → 跳过
6. 可选「严格校验」（`strictHash`）：≤10MB 文件逐字节比对内容（FNV-1a 64 位，避免额外依赖）

### 5.3 模式语义

| | 增量替换（默认） | 整体替换（镜像） |
|---|---|---|
| 新增 / 覆盖 | ✅ | ✅ |
| 目标多余文件 | 保留 | 移入回收站（可在设置中改为永久删除） |
| 等价命令 | `robocopy /E /XO` | `robocopy /MIR`（但删除走回收站） |
| 风险 | 低 | 高，执行前提示确认（托盘菜单触发同样会确认） |

### 5.4 边界与异常处理

| 场景 | 处理 |
|---|---|
| 文件被占用/写入中 | 退避重试（0.3 / 1 / 2s × 3），仍失败记入失败清单 |
| 同一文件连续变更 | 防抖合并，只处理最终状态 |
| 同步过程中又有新变更 | 置 pending，本轮结束后按方式再跑一轮 |
| 磁盘满 / 无权限 | 记录失败项，任务继续，完成后汇总通知 |
| 监听目录不存在（U 盘未插 / 网络盘掉线） | 不退出，进入「等待重试」，超限后自动停止监听并提示（见 5.5） |
| 目标目录不存在 | 自动递归创建（含多级父目录）；创建失败才报错 |
| 目标在源目录内部 | 启动时直接拒绝（含源=目标） |
| 手动关闭窗口 | 默认最小化到托盘，进程继续监听 |
| 重复启动 | 单实例互斥，唤起已有窗口 |
| 通知发送失败 | 写入日志降级，不影响同步 |
| config.json 带 BOM | 读取时剥离 BOM，避免配置被静默重置 |

### 5.5 监听目录缺失：等待重试状态机

`watch.rs` 用一条监督线程维护完整的监听到重启的闭环，状态只有三种：

| 状态 | 界面表现 | 转入条件 |
|---|---|---|
| 监听中 | 状态灯绿色「监听中」 | 目录可用且 watcher 建立成功 |
| 等待重试 | 状态灯橙色「等待目录 · 第 i 次」+ 黄色提示条倒计时 | 目录不存在 / watcher 建立失败 / 事件循环中断 |
| 已停止 | 状态灯灰色「未监听」+ 红色提示条 | 用户停止，或重试超限自动停止 |

```
loop:
  目录不可用 → wait_once(reason)     ── 计数 +1
      ├─ 超过「最大次数」或「最长等待」 → give_up()：停止监听 + 通知 + 红色提示
      └─ 否则按间隔逐秒倒计时后重试
  目录可用 → 建立 watcher
      ├─ 首次建立 / 从缺失中恢复 → 通知（仅恢复时）+ 比对两个目录（见 5.6）
      └─ 进入事件循环（recv_timeout = 防抖窗口）
            └─ 每 5s 健康检查 is_dir()，目录消失则回到 wait_once
```

关键实现点：

- **不阻塞 IPC**：`start_watch` 只做结构校验（顺带创建目标目录）就返回，等待与重试全在线程里。
- **会话代号 `generation`**：`start_watch` / `stop_watch` 都会递增，旧线程所有状态写入都会被丢弃，
  避免「停止后又被旧线程改回等待中」的竞态。
- **每秒刷新倒计时**：等待期间每秒推送一次 `sync://state`（仅在异常态，正常监听时无额外开销）。
- **手动同步不等待**：`validate_dirs` 仍要求目录存在，用户点「立即同步」时直接得到错误提示。
- **目录消失时不触发同步**：事件队列里已有待处理变更、但 `is_dir()` 已为假时，直接转入等待，
  不再尝试一次注定失败的同步。
- **超限停止**：`give_up` 走 `stop_watch` 收尾（状态灯归位、清除等待信息），并额外推一条
  `sync://alert` 让界面显示可关闭的红色提示条。
- **过滤目录元数据事件**：`notify` 会把「目录的修改/访问时间变化」报成 `Modify(Any)`，
  而 `WalkDir` 扫描目录本身就会触发这类事件，若不处理会形成「扫描 → 事件 → 自动同步」的
  自激循环。事件循环里丢掉「`Modify` 且路径全是目录」的事件（`Modify(Name)` 重命名保留）。

### 5.6 启动 / 恢复时的目录比对

监听建立成功后立刻做一次**只读比对**（`sync::diff_dirs`），判定规则与同步引擎共用
`need_copy`，因此不会出现「说有差异却同步了 0 项」：

| 结果 | 行为 |
|---|---|
| `total == 0` | 只写一行日志「两个目录内容一致，继续监听」，不做任何事 |
| `total > 0` | 推送 `sync://diff`，前端弹「发现目录差异」对话框 |

- 比对在**独立线程**里跑，不阻塞事件循环；扫描期间的真实变更照常由 watcher 收下。
- 有差异时弹窗列出 `新增 / 更新 / 删除` 项数；整体替换模式额外提示「会移入回收站 N 个文件」，
  所以确认后直接执行 `sync_now`，不再叠加第二次镜像确认弹窗。
- 用户点「暂不同步」只关闭弹窗，仍保持监听；后续变更照常按自动/手动方式处理。
- 触发时机仅两种：本次会话**首次**建立监听、或目录**从缺失中恢复**。监听器因错误重建
  不会重复打扰。
- 提示**必须被看到**：推送事件前调用 `set_prompt_mode(true)`（`show` + `unminimize` +
  `set_always_on_top(true)` + `set_focus`），窗口即使被收进托盘或压在别的程序后面，
  也会跳到所有窗口最上层；前端在用户作答 / 跳过提示后调用 `set_prompt_mode(false)` 解除置顶。
- 若此刻正在同步、或已有其它弹窗打开，则跳过本次提示（同样会解除置顶）。

### 9.1 为什么不是「单文件 exe」

`webview2-com-sys` 的链接方式按目标环境二选一：

```rust
#[cfg_attr(target_env = "msvc",  link(name = "WebView2LoaderStatic", kind = "static"))]
#[cfg_attr(not(target_env = "msvc"), link(name = "WebView2Loader.dll"))]
```

即 **只有 msvc 目标静态链接**；`x86_64-pc-windows-gnu` 只能动态链接
`WebView2Loader.dll`（crate 内自带 `x64/WebView2Loader.dll`，构建脚本会把它拷到输出目录）。

该 DLL 无法用 GNU 工具链静态替代：`x64/WebView2LoaderStatic.lib`（10MB）是 MSVC C++ 产物，
未定义符号里含 `??_U@YAPEAX_K@Z`（`operator new[]`）、`__security_cookie`、
`__guard_dispatch_icall_fptr` 等 MSVC 运行时符号，`ld` 无法解析。

**结论**：程序目录必须是 `FileSync.exe` + `WebView2Loader.dll`。单独把 exe 拷走会出现
「进程存活但无窗口、日志无输出」的假死（导入表解析失败），不是程序缺陷。

### 9.2 安装包（NSIS）

`scripts/installer.nsi` + `scripts/build-installer.ps1`，用免安装版 NSIS 编译（无需管理员）：

| 特性 | 说明 |
|---|---|
| 安装位置 | `%LOCALAPPDATA%\Programs\FileSync`，`RequestExecutionLevel user` |
| 组件 | 主程序（只读）/ 开始菜单快捷方式 / 桌面快捷方式，带中文组件描述 |
| 升级 | `.onInit` 读卸载项，静默运行旧版卸载器（`/S _?=<dir>`）后再安装 |
| 覆盖前 | `taskkill /IM FileSync.exe /F /T` 结束自身与 WebView2 子进程 |
| 自启保持 | 若 Run 项已存在，改写为新安装路径 |
| 卸载 | 删快捷方式、程序文件、卸载项、AUMID、Run 项；弹窗询问是否删除 `%APPDATA%\FileSync` 与 `%LOCALAPPDATA%\FileSync`（**默认保留**，`/SD IDNO`） |
| 环境检查 | 缺 WebView2 Runtime 时提示，可继续或中止 |
| 界面 | MUI2 + `SimpChinese`，脚本存为 **UTF-8 with BOM**（否则中文按 ANSI 解析） |

- 绿色版（`dist\FileSync\`）与安装包共用同一 exe，行为一致
- 依赖系统自带 WebView2 Runtime；首次运行在 `%APPDATA%\FileSync\` 生成配置与日志
- `tauri.conf.json` 的 `bundle.targets` 仍写着 `nsis`，但走的是 `cargo tauri build` 那套
  （需联网拉 `nsis-tauri-utils`），本机改用上面的独立 NSIS 脚本，两者产物等价
- 开机自启写 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run\FileSync`，绿色版同样有效
- 若本机装有 VS C++ 工作负载，可换 msvc 目标得到真正的单文件 exe
